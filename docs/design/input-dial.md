# The input dial (`src/web/src/lib/mobile-input-dial.ts`)

The floating control in the bottom-right of each terminal iframe — the root, its arc of targets, and the satellite button it carries above it, `.dial-chat` — is **the app's chrome wherever the footer is not**. It lives inside the ttyd document rather than in the parent, because `preventDefault` on a same-document pointer gesture is what keeps the iOS software keyboard up; a control in the parent would dismiss it and could not reopen it.

**`.dial-chat` opens the view picker, not the chat** (App's `mobileViewsOpen`, a controlled menu on an invisible anchor in the parent, like HostSwitcher's): Bots is always a place to go besides Chat, and plugin views add more, so a single destination button would strand them. A plugin view covers the dial, so it carries its own picker button in the same corner; Bots covers it too, so its list header and every bot's own header (its chat, or its stopped page) carry the button instead (the anchor moves to the top-right there, so the menu opens under the header rather than over the composer). The picker has Sidebar, which is how a phone opens the right sidebar: it is not a button of its own.

- **The sidebar is a picker entry, not a button, which keeps the root in the corner.** A satellite below the root would need ~42px of clearance plus its own radius, which lifts the whole box off the thumb's home corner; with Sidebar in the picker the root sits on the 18px line (`DIAL_BOTTOM`), the picker button hangs above it, and nothing paints below, so `TERMINAL_BOTTOM_GAP` clears the same rows. Lasso's arc is two targets (Search, Host), on the root arc's own r=220 and 29° spacing so a level change slides a target along one curve instead of onto a different one.
- **Two conditions mount it, and either alone is enough**: a coarse pointer (asked of the IFRAME) or a viewport below `md` (`(max-width: 767px)`, asked of the **PARENT**). The parent is not a detail: this document is only the terminal *column*, so a width query here measures the panel split — a wide window with a wide sidebar would read as narrow and grow a dial beside a footer that is still there. `watchDialConditions` ORs them and mounts exactly **once**, since a phone matches both and a dial per condition would be two dials in one document with one teardown.
- **The width half exists because a narrowed desktop used to have no chrome at all.** The footer is `md:flex`, so dragging a window under 768px takes New, the host menu, both sidebars, the shortcuts sheet and Chat off the screen — and with a mouse and no touchscreen nothing replaced them. The dial already works a pointer (a click opens the ring, a click on a target fires it; the CSS has carried `cursor: grab` and a hover state throughout), so the fix mounts the existing control rather than growing a second copy in the parent document.
- **Both conditions are WATCHED, never sampled at boot.** A hybrid folded into tablet mode, a keyboard case detached, a window dragged across the breakpoint — each flips one of them, and a sampled gate is wrong in one direction or the other for the rest of the page's life. The teardown drops the `#terminal-container` gap with the stylesheet, so a window widened back past `md` gets its bottom rows back.
