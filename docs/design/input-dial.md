# The input dial (`src/web/src/lib/mobile-input-dial.ts`)

The floating controls in the bottom-right of each terminal iframe — the root, and the keys button it carries above it, `.dial-keys` — are **the app's chrome wherever the footer is not**. They live inside the ttyd document rather than in the parent, because `preventDefault` on a same-document pointer gesture is what keeps the iOS software keyboard up; a control in the parent would dismiss it and could not reopen it.

**The root is the view picker, one tap, and wears its grid glyph** (lucide's `LayoutGrid`, built as SVG in the iframe's document by `gridGlyph`, the same glyph as every other picker button). It emits the `views` command, which opens App's `mobileViewsOpen`, a controlled menu on an invisible anchor in the parent, like HostSwitcher's. The root used to open a ring of app commands (New, a Lasso branch with Search and Host, and a Common keys branch); with the chat view as the phone's way to read and answer an agent, those are destinations rather than input, so they are picker entries now: views first, then New, Search (`openSearch`, ⌘K's answer for the view on screen), Host and Sidebar. Every view that covers the dial carries the same picker button instead, so a phone moves between views one way everywhere: a plugin view in the dial's own corner; the chat in its header, where the button replaced a Terminal-only one; Bots on its list header and every bot's own header (its chat, or its stopped page). For the chat and Bots the anchor moves to the top-right, so the menu opens under the header rather than over the composer. **The anchor is not `md:hidden`**: a coarse pointer mounts the dial at any width (a phone on its side, a tablet), and a root that opened a hidden menu would do nothing. **The root opens the picker on `click`, and the menu opens to the LEFT of the dial**, never over it: a tap's trailing click is hit-tested at the finger in the top document, so a menu opened on the pointerup and drawn under the finger (it was anchored in the corner) got its bottom item, Sidebar, picked by the same tap.

**`.dial-keys` opens the common keys directly**, the only ring left. The keys keep the arc around the ROOT's centre (the thumb's corner) and are hit-tested against it, but their lines start at the keys button (`KEYS_DX`/`KEYS_DY`), so the ring reads as opened from the button that opened it. A tap opens it and a second tap closes it; a press that slides onto a key sends it on release, the hold-and-slide the root used to carry. The ring stays open after a key so a run of arrows is a run of taps, and it closes on a tap anywhere else (the dismissal swallow below), on Escape, or when the root is tapped. It wears the accent fill while open (`aria-expanded`), which was the root's armed state.

- **Nothing paints below the root, which keeps it in the corner.** A button below the root would need ~42px of clearance plus its own radius, which lifts the whole box off the thumb's home corner; the root sits on the 18px line (`DIAL_BOTTOM`), the keys button hangs above it, and `TERMINAL_BOTTOM_GAP` clears the same rows.
- **Two conditions mount it, and either alone is enough**: a coarse pointer (asked of the IFRAME) or a viewport below `md` (`(max-width: 767px)`, asked of the **PARENT**). The parent is not a detail: this document is only the terminal *column*, so a width query here measures the panel split — a wide window with a wide sidebar would read as narrow and grow a dial beside a footer that is still there. `watchDialConditions` ORs them and mounts exactly **once**, since a phone matches both and a dial per condition would be two dials in one document with one teardown.
- **The width half exists because a narrowed desktop used to have no chrome at all.** The footer is `md:flex`, so dragging a window under 768px takes New, the host menu, both sidebars, the shortcuts sheet and Chat off the screen — and with a mouse and no touchscreen nothing replaced them. The dial already works a pointer (a click on the root opens the picker, a click on ⌘ opens the ring and a click on a key fires it; the CSS carries hover states throughout), so the fix mounts the existing control rather than growing a second copy in the parent document.
- **Both conditions are WATCHED, never sampled at boot.** A hybrid folded into tablet mode, a keyboard case detached, a window dragged across the breakpoint — each flips one of them, and a sampled gate is wrong in one direction or the other for the rest of the page's life. The teardown drops the `#terminal-container` gap with the stylesheet, so a window widened back past `md` gets its bottom rows back.
